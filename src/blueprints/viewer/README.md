# Blueprints WebGL viewer

Custom offline viewer shell (not a third-party app). Three.js is bundled only as a renderer/loader.

## Features

- Liquid-glass controls sheet (phone: bottom sheet with grabber detents peek / partial / full; wide: classic right pane — no grabber, top-right toggle, edge swipe to open, swipe pane to close except on sliders/controls); light/dark via `prefers-color-scheme`
- Part outline groups (Walls / Roof / Interior) with per-group and per-leaf **opacity** sliders (tap toggles 0 ↔ last value; scrub only by dragging the thumb — cooperative range, no click-to-seek). Editing a leaf detaches it from the parent group so later group fades leave it alone; a **Sync** button (right of the slider) reattaches and matches the group. Translucent parts while the camera, a slider, or a scene change is in motion are one sorted-alpha draw (depth test on, so faces do not flicker). The next still frame runs a full-resolution depth peel. Faded faces that share a material are one draw per layer (a gable is thousands of meshes and a few dozen materials). Batches are built while the camera is still moving, so letting go does not also pay the merge. Faded meshes keep `renderOrder = 0` so opaque `LAYER_DEPTH_BIAS` does not invert shell order. Opacity 0 hides a part (also omitted from AR).
- **Edges** modes (Materials sheet): **None** / **Transparent** / **Opaque**. CAD hard-edge overlay via fat `LineSegments2` strokes (black, ~2.5px) plus section-cut silhouettes when not None. Strokes live on layer 1. While the camera moves, every stroke is drawn against opaque-face depth, so lines show through glass. Once the view settles: **Opaque** strokes (and strokes of unfaded parts) still do that, so a solid line stays visible through transparent faces and is hidden only by opaque faces in front. **Transparent** strokes are drawn into the peel layer of their own surface, so a line behind glass is blended behind that glass rather than stamped on top or dropped. A 0.35 mm view-space pull plus one face-bias step (only when the program writes log depth — `USE_LOGARITHMIC_DEPTH_BUFFER` since three r180, `USE_LOGDEPTHBUF` before; never overwrite with `gl_FragCoord.z`) keeps a stroke on its own face. The pull stays under the tile thickness, so a line behind another solid does not show through. Tile strokes are the exposed cap only; grout is one centreline per joint, and tile edges that duplicate that centreline are dropped. Persists in `localStorage` (`blueprints.edgeMode`). Default Transparent. Overlays are omitted from AR and Measure picking.
- **Frame cost:** redraw only when the camera, canvas size, cuts, opacities, materials, locale, or labels change, plus one peel frame after that motion stops. The moving frame, and the frame that first shows a new scene or setting, are a single sorted-alpha draw. The next still frame peels merged batches (at most 12 layers). `polygonOffset` does not survive logarithmic `gl_FragDepth`, so `LAYER_DEPTH_BIAS` is applied in the face shader. Opaque frames draw edges against the colour-pass depth. Scene changes apply every leaf opacity, then clip and rebuild edges once. Opacity sliders do not rebuild fat lines. A cut drag moves clip planes live and rebuilds silhouettes when the thumb is released.
- **Material modes** (Materials sheet, `localStorage` `blueprints.materialMode`): **Solid** (flat diagrammatic colours, fixture colour coding), **Shaded** (the same palette lit, with procedural bump/roughness presets in `materials.js` `SHADED_PRESETS`; this was called "Realistic" until 2026-11-12), and **Realistic** (catalogue PBR, below). Petr asked for real colours and textures under the Realistic name and to keep the old look under another name (2026-11-12). "Shaded" is SketchUp's name for the same idea: its face styles include *Shaded* ("solid colors and basic shading but without any textures"), *Shaded with Textures* and *Photoreal Materials* (PBR maps) ([SketchUp Help: Styles Panel](https://help.sketchup.com/en/sketchup-ipad/styles-panel)). The stored value `realistic` keeps its key, so a saved preference opens the new Realistic look; nothing is migrated.
- **Realistic** (`realistic.js`, `catalogue.js`, `assetSlots.js`): materials come from `inputs/materials/catalogue.yaml` (contract: `docs/materials/README.md`). Nothing about it loads until Realistic is picked: the YAML (`../materials/catalogue.yaml?v=<hash>`, copied by `ensure_viewer_shell()`) and then one texture set per entry, fetched as meshes need them; meshes keep their Shaded look until their maps arrive. A map path `docs/materials/…` resolves to `<catalogue dir>/../materials/…`. Each mesh picks the most specific selector across entries: `ids` (100) over `id_pattern` (10) over `label` (1); ties go to the first entry. Ids are compared as written and in the form GLTFLoader leaves in node names (`[ ] . : /` dropped, so `BED-1.11` arrives as `BED-111`); write `id_pattern` so both match. A mesh with no entry keeps a neutral PBR fallback (glazing and screens get glass), and `blueprintsRealistic.report()` lists unresolved meshes, ties and failed textures.
  - Materials: `MeshStandardMaterial`, or `MeshPhysicalMaterial` when the entry sets transmission, clearcoat or sheen. Colour maps are sRGB, data maps linear, normal maps OpenGL convention; no colour map means `base_color` is the albedo. Each (entry, part label) gets its own material so opacity, depth bias and the peel patch stay per label; texture sets are shared.
  - UVs: Realistic swaps in world-metre box-projected UVs (a 1 m face spans 1 m of texture, `repeat = 1 / tile_size_m`) and restores the GLB's own UVs on leave. Entries with `rotation_deg` align V with the part's longest extent first, then rotate.
  - Stage: RoomEnvironment IBL (`environmentIntensity` 0.5), one shadow-casting sun with PCF soft shadows (redrawn only when a door, window or the content moves), a hemisphere fill, ACES Filmic. The models have no floor slab, so a ground plane under the model is painted with `floor-pu-living` (`STAGE_FLOOR_MATERIAL`); it ignores taps and the label overlay pass.
  - Phones: `?quality=low|high`, default low on a coarse pointer, iOS or Android. Low caps textures at 1024 px, anisotropy 4 and a 1024 px shadow map, and draws glass as blended PBR (environment reflections, opacity from the entry's transmission) because three.js redraws every opaque object into a transmission target whenever glass is in view, which doubled the draw calls on the kitchen view (1395 to 2787). High is 2048 / 8 / 2048 with real transmission.
  - Fixtures as glTF (`fixtureAssets` viewer option: `[{ selector: {label, ids?, id_pattern?}, url, fit?: "contain" | "none" }]`): the asset replaces the generated geometry of each matching element, placed bottom-centre in its box. The generated meshes stay for taps, highlighting and the Parts list but are not drawn. glTF material slots named by catalogue id take the catalogue material (`swapCatalogueMaterials`); other slots keep the asset's own material. Only in Realistic.
- Camera presets (Iso / Front / Side / Top) — orientation only
- **Custom scenes** (optional, model-specific): extra View buttons after the builtins. Each scene can set camera pose (`position` / `target` / optional `up`), optional FOV or orthographic ISO (`projection: "ortho"`), optional section cuts, and optional part opacities (`opacity` + `opacityDefault`). Loaded from `docs/models/<id>.scenes.json` (Pages) or embedded in the offline HTML export. Coordinates are **glTF world metres after OCCT’s Z-up→Y-up root rotation** (`(x,y,z)_cad → (x,z,−y)`): X eave↔eave, Y up, Z = −(kitchen↔living). Use `blueprints.scenes.cad_mm_to_gltf_m`. Deep-link with `?m=<id>&scene=<sceneId>` (e.g. `viewer/?m=obyvak&scene=soffit`). Selecting a custom scene updates the URL via `history.replaceState`; orbiting or picking Iso/Front/Side/Top clears `scene` so the bar matches the View highlight.
- **FOV / ISO:** View-section slider (30–120° horizontal FOV, default 75°). Right detent is **ISO** (real orthographic). Drag adjusts FOV or snaps into ISO; tap toggles ISO ↔ last perspective FOV. Framing is adjusted so on-screen model size stays roughly constant across FOV / projection changes.
  - **Known ISO issues:**
    1. Coplanar faces are separated by the log-depth shader bias (`applyLayerDepthBias`). Polygon offset is still set, but ISO overwrites `gl_FragDepth` with `gl_FragCoord.z`, so the shader step is the one that counts.
    2. After changing FOV then switching to ISO, a phantom clip that looks like a section cut can appear even when no cut is active. Usually not triggered by orbiting alone while already in ISO — suspect near/far or frustum handoff in the perspective→ortho transition (`enterOrtho` in `main.js`). Do not treat this one as fixed.
- **Section cuts**: sheet sliders clip the model with planes locked to the view direction at first interaction (architectural: near side removed). Multiple locked cuts AND together. After a cut is locked, orbiting the camera adds another draft slider for a new plane. Left end of each slider = no cut; right = fully past the model. Sheet section order: View → Sections → Parts. Cut sliders use a cooperative control (`touch-action: pan-y`) so vertical sheet scroll still works when the gesture starts on the thumb — only horizontal **drag** is consumed (tap does not seek; native `<input type="range">` monopolizes the touch on many mobile browsers). Clipping does not fill a face: each cut gets a solid cap in the part’s own material (`sectionCaps.js`), with openings left empty, so a solid sliced on both ends stays solid instead of an open tube. Those cap meshes go into AR with the part; the export clip does not add a second fill.
- Partial sheet (phone) / open side sheet (wide) shifts the camera view offset so the model stays centered in the visible safe area above/beside the sheet; peek, closed, and full clear the offset.
- **AR**: generates a USDZ in-browser from the current visible geometry (hidden parts omitted, section cuts baked into mesh) and opens Quick Look. No server round-trip. GLB is already metres (glTF); models larger than 2 m are scaled to a ~0.45 m tabletop and lifted slightly above the plane for indoor AR. Quick Look transparency sorting may be weaker than the web depth-peel path.
- **Hinged doors:** a tap or click on a single swing leaf swings it 90° about its hinge (about half a second, ease-in-out). A drag still orbits; Measure consumes taps while it is on. Hinge side and swing come from the model (`<id>.doors.json`: width, `HingeSide`, `Swing`). Sliding and pocket leaves are described below. With the leaf open, a tap anywhere on its closed rectangle closes it. That rectangle is an invisible proxy: it is not in the scene, its `raycast` is a no-op, and zoom, pan, orbit pivot, and Measure skip `userData.bpHitProxy`. Tap resolution (`interactions.js`, `tapTargets.js`; Petr, 2026-11-12), first match wins: (1) **direct hit** — the nearest solid a registered interactive claims (door, drawer, light, switch, window, live blind), unless an opaque solid sits more than 5 cm in front of it (faded parts and glass hide nothing); if two handlers claim one solid, the higher priority wins; nothing below can steal a direct hit. (2) The farthest open doorway the ray enters before the first opaque solid closes. (3) **Extended targets** — a flat 44 pt (Apple HIG) circle on screen around the centre of every shown interactive; each rocker half is its own target (up/down, and left = `rocker-1` on a double), so a distant switch still has ~22 pt above for up and below for down. Centres off screen, behind the camera, or behind an opaque solid are skipped. Where circles overlap the target nearest the camera wins; within 5 cm of depth (or halves of one element) the centre nearest the finger wins. Nothing else: a tap never reaches through opaque geometry (Petr, 2026-11-13, "I can literally open doors through multiple walls"; the old fourth pass that pressed the nearest claimed solid anywhere on the ray, and closed doorways behind walls, is gone). Only surfaces that are drawn at the hit point count, as targets and as blockers: shown through every parent, not hidden in the inspector, not faded to 0, and not cut away by a section plane (raycasts ignore clipping, so `isClippedAt` applies the cut planes; an extended target whose centre is cut away is dropped). Faded parts and glass never block, in Solid, Shaded and Realistic alike: a `glazing` or `screen` part (Solid paints glazing opaque blue), a transmission material, or any translucent material. So a door seen through a window can be tapped; an operable sash in front still claims the tap first. Geometry a Realistic glTF asset stands in for still blocks. A 5 cm tolerance lets a switch or socket on a wall face keep its target, including a flush box whose centre sits inside the wall. Long-press uses the same order and opens the inspector on that element's info screen (a direct or extended target, otherwise the front solid). No outline is drawn. Standing inside the swing does not change the rule.
- **Sliding and pocket doors:** a tap on the leaf slides it open or shut with the same timing as a hinged leaf; with it open, a tap through the empty opening shuts it. Records are `kind: "sliding"` in `<id>.doors.json`: `start` and `end` (the leaf's jamb ends, glTF metres) and `panels`, each a `span` (fraction of the leaf) and its full opening `slide`. The model keeps the leaf as one slab, so a two-panel door is drawn as two copies of the slab, each squeezed to its half (`doors.js` `bindSliding`). `models/ground_floor.py` `_sliding_panels` decides the panels: `SLIDING_TO_LEFT` / `SLIDING_TO_RIGHT` slide the whole leaf its width toward the start or end jamb; anything else, including no `OperationType`, is bi-parting, two halves each sliding half the width over its own jamb. That is bedroom OP03, the double pocket into 1.10 Šatna (`docs/electrical/rooms/1.11-geometry.md`). The living-room pocket doors OP24, OP25 and OP33 are single leaves (`SLIDING_TO_RIGHT`/`SLIDING_TO_LEFT`, from the DWG's parked leaves; Petr, 2026-11-12).
- **Sectional (garage) doors:** the garage doors D5/D6 (OP50/OP49; Petr, 2026-11-12) are `OperationType: USERDEFINED` with `Pset_BlueprintsDoor.UserDefinedOperationType: SECTIONAL_OVERHEAD` (IFC4 has no sectional type). Records are `kind: "sectional"`: the leaf's jamb ends `start`/`end` at mid-height and the centres of its sill and head, `bottom` and `top` (glTF metres), `inward` (unit, into the building), `sections` and `bend`. `doors.js` `bindSectional` draws the slab as that many squeezed copies; `sectionalTrack` runs each section up the opening, round a quarter bend of radius `bend`, then level inward under the head, so a tap raises the door into the ceiling and a second tap lowers it, same timing as a hinged leaf. It is a simplified animation, not a product's track. Feedback is an up or down arrow (`kind: "lift"`). Data-driven: any door with that operation type gets it, not an id list.
- **Windows:** which panes open comes from the model (`<id>.windows.json`, one record per window: `operable` and `panels`, each with its IFC panel `operation`, world box `min`/`max`, `center`, and `slide`, glTF metres; facts in `docs/design/ground-floor.md`, Windows). A tap on a pane that opens slides it by its `slide` and back, easing over the same 500 ms as a door; all face meshes of the pane move together, sorted into panels by the panel boxes (`windows.js`). A fixed pane never moves and claims no tap, and a window with no pane that opens (fixed glazing, e.g. the bedroom west windows) claims no tap and has no 44 pt target, so a tap on it goes through to what is behind. On a part-opening window the 44 pt target sits on the sash. Without a record (the offline export HTML) a pane slides 80 % of its width along its parent's +X, the pre-panel behaviour.
- **Lift-up fronts (linkages):** a tap on either front of a kitchen wall cabinet's bi-fold, or a lever, runs its opening motion and a second tap shuts it, 900 ms. Records are `kind: "linkage"` in `<id>.doors.json`: `joints`, each with `elements` (`{element, center}`, one mesh each, matched like a drawer), a `pivot` point and `axis` (glTF metres, as built), `angles` (radians, right-handed about `axis`, even samples from shut to open, interpolated), `parent` (null, or the index of an earlier joint whose pivot it rides on; its angles are then relative to that joint) and an optional `stretch` `{along, scales}` (a telescoping arm grows along `along` by one scale per sample), plus `duration_ms`. `doors.js` `bindLinkage` builds one pivot group per joint. Generic: any part chain that turns about lines can use it. The kitchen's are written by `models/ground_floor.py` `_linkage_motion`; the motion itself is in `docs/design/kitchen-cabinets.md` (“Opening in the viewer”). Feedback is an up or down arrow.
- **Drawers:** a tap or click on a drawer slides it out by its full extension and back (same timing as the doors). Records are `kind: "drawer"` in `<id>.doors.json`: `element` (the cabinet's yaml id), `center` (matches one mesh under that element), `slide` (glTF metres). The model derives them from the cabinet parameters; see `docs/design/kitchen-cabinets.md`.
- **Interaction feedback:** every tap that drives something shows a short glyph at it, a fixed 36 CSS px whatever the camera, that drifts up about 36 px and fades over 700 ms (fade only with `prefers-reduced-motion`). Each press spawns its own glyph, so a quick burst stays readable. Rocker: an up or down arrow at the pressed half (per half on a double rocker); presses by other Home clients show the same arrow. Sectional doors: an up arrow when opening, down when closing. Drawers, windows and sliding doors: a straight arrow along the slide as projected on screen, for open and close (one per panel on a bi-parting door, with one haptic). Hinged doors: a quarter-arc arrow from the leaf's current position toward where it swings, bending around the hinge on screen, so open and close read as opposite turns. Lights: a ring pulse. Dark fill with a white outline, readable on white walls and the dark background. Haptics: `navigator.vibrate(10)` where it exists (Android Chrome and Firefox). iOS Safari has no Vibration API, but since iOS 18 toggling a native `<input type="checkbox" switch>` plays the system selection haptic, also when script clicks its `<label>` during a user gesture. On a touch device without `vibrate`, `haptic()` adds a hidden label+switch to `<head>`, clicks it, and removes it, synchronously inside the canvas `pointerup` tap handler (iOS ignores it outside a gesture). Older iOS and desktop get nothing; failures are silent. Code: `feedback.js` (`showFeedback({ worldPos, kind, direction | worldDir | hinge+to })`), called where actions dispatch (`main.js`, `doors.js` `onToggle`); tests `feedback.test.mjs`. `window.blueprintsFeedback` exposes the layer for debugging.
- **IFC inspector (POC):** a long-press (~500 ms, cancelled if the finger moves) on a visible solid opens the inspector directly on that element's info screen (Petr, 2026-11-12: ditch the popover, go straight into the inspector; the old "Show in inspector" button is just Back). Info shows the name first (tap it to show the GlobalId, tap again for the name), then type, storey, space, known dimensions, a note (property sets, cable number, circuit, role), and actions: the interactions registry (door and window open/close, light toggle, switch press; a wall has none) plus Frame, Hide / Unhide, Hide all others, and Unhide all others. A group's actions apply to its members recursively. Hit proxies are not targets. A long-press on a solid with no IFC record still opens info ("No IFC record"). The inspector is a page inside the same sheet; Back from info returns to the tree, Back from the tree returns to the menu (the model). On a phone it opens at the half-height detent so the model stays visible above the sheet. A segmented picker is visible only at the inspector root, not on an info screen (Petr, 2026-11-12: "the segmented picker shouldnt be visible on the info screen, only at root of the inspector"). It switches between two tabs, with a short slide animation: **Spatial** is project → site → building → storey → space → elements, plus aggregate/nest children, collapsed except the path to a revealed row, with a breadcrumb of the focused path. **Groups** lists top-level `IfcGroup` / `IfcSystem` rows (Furniture — kitchen bay groups as children, plus loose furniture such as the sofa as member elements — Electrical, and any nested child groups such as a kitchen bay); there is no path bar on this tab. Indent is 12 px per level and stops after four levels. The first tap on a row pulses that element (or a group's members). A second tap on the same row eases the camera onto it. Long-press a row for Info, or to hide or unhide it (and its children or group members, recursively) or everything else. Element info lists the groups it belongs to; group info lists parent groups, child groups and child elements as separate tappable sections. Tapping a group switches to the Groups tab and opens its info; tapping an element switches back to Spatial and reveals it. The picker stays hidden while info is open; the underlying tab is updated so Back lands on the right root. A back step returns through that chain, then to the tree. Show all appears while anything is hidden. Hidden state lasts for the session only and is not written to the URL. Hidden elements are not tappable. The index is `docs/models/<id>.ifc.json`, cut from the yaml-ifc model. Groups are a top-level list in that file, not rows in the spatial tree (Petr, 2026-11-12). Mesh names `part__yamlId__` keep the part groups and point at that row.
- **Walk-through:** pinch and the wheel zoom toward the surface under the fingers or cursor, so the step is the distance to that surface instead of shrinking to nothing at the orbit center. A miss, or a surface closer than about 30 cm, leads the center forward and zoom keeps moving through the room. Two-finger and right-button pan use the grabbed depth, so the point under the fingers stays under them. One-finger orbit from outside still turns about the framed center. Once the surface under the finger is much closer than that center, the drag turns about the point where the finger went down. A tap does not move the camera, so hinged doors still open.
- **Measure (experimental):** top-bar tool next to AR. AutoCAD-style place/confirm (trackpad: crosshair on enable; touch: drag with finger-offset cursor, tap-anywhere confirms without re-picking). Mesh snaps (vertex / edge / face) plus perpendicular width snap between parallel edges on a face. **Not a finished contract** — UX and snap behavior will keep changing; do not treat current behavior as gospel when extending the viewer.
- **Live Home (Plan step 7 of [pteasima/Home](https://github.com/pteasima/Home)):** on a model whose IFC index has lights, switches, sensors or actuators (today `ground_floor`), the viewer connects to the Home state API and shows real device state. Contract: Home's `api/openapi.yaml` and `api/schemas/` (read at Home `81f5b6a`); no code dependency. Devices are matched by IFC `GlobalId`, the key of `<id>.ifc.json`. A **Home** section in the sheet (above Language) switches **Live** / **Off** and shows the status; the choice persists in `localStorage` (`blueprints.homeMode`, default Live). `?home=off|live` overrides it for one load, and `?homeUrl=https://…` points at another server (default `https://home-test.tail9f879b.ts.net`). Live: GET `/health`, then WebSocket `/events` (snapshot, then `state` and `switch` messages). A light that is off is a dull grey with no glow. A light that is on is an obvious bright glow tinted by its colour temperature (amber when warm, white when cool; `lightOnHex` in `homeLive.js`), in Solid, Shaded and Realistic (Realistic paints it on a clone of the `light-diffuser-opal` material); a lower CurrentLevel weakens it. The first version drew on as a pale cream and left off in the fixture's yellow, and Petr read them the wrong way round on his phone (2026-11-12). Offline taps use the same two looks (3000 K for on); before any tap a light keeps its model colour. A tap on a light sends `toggle` (POST `/devices/{globalId}/commands`); the glow changes only when Home pushes the new state. A tap on a rocker presses it through the simulation route (POST `/simulate/devices/{globalId}/press`, test server only): the upper half is up, the lower half down, and on a double rocker the left half as seen facing it is `rocker-1` (Home has not decided which half is rocker 1). Every `initialPress` from Home, including presses by other clients, animates the rocker. The inspector info screen adds a **Live** block (state, level, kelvin, CCT channels, contact, occupancy, blind position) and, for live rockers, Up / Down buttons per rocker; a blind motor (`IfcActuator`) gets Open / Close / Stop only while live. Offline fallback: if Home is unreachable, the connection drops, or the mode is Off, taps behave exactly as before (local light toggle, press animation) and the client retries with backoff (2 s up to 60 s). A drop keeps the last state drawn; choosing Off puts every light back in its model colour, as on load. `window.blueprintsHome` exposes the client for debugging. Code: `homeLive.js`, tests `homeLive.test.mjs`.
- **Scene drawings:** a custom scene may carry `title`, `project`, and `annotations` (callouts, dimensions, and `kind: "line"` polylines). Anchors and line `points` are CAD millimetres. A line may set `dashed`, a `#rrggbb` `color`, and `arrow` (head on the last point). A callout with `leader: false` is the text only. A callout or dimension may set `color` (`#rrggbb`) and `size` (a font multiple). A scene `annotationColor` colours every dimension and callout (lines and labels) on that plate; geometry lines stay black unless they set their own `color`. `edges` is `none`, `transparent`, or `opaque` for that scene. Callout `offset` is a fraction of the view (from the primary `anchor`); optional `tips` add extra leader tips to the same label. Dimension `offset` is a fraction of the view height, to one side of the measured line. Text is `{en, cs}` and follows the language toggle. Labels are small haloed notes (no chip), sized from the view, and not part of the GLB. **Labels** on the top bar hides and shows them. Builtin Iso/Front/Side/Top clears them; orbiting keeps them on their anchors. A cut may pass through an `anchor` (CAD mm) instead of a bbox-relative `t`. `verticalExaggeration` scales CAD Z about elevation 0 (glTF Y) for that scene only; the plate title should say so. Dimension text on an exaggerated scene is authored, because the measured length includes the scale.
- **Drawing** (top bar): active custom scene only. Re-applies that scene’s camera, renders an A3 landscape plate (white background, opaque edges, labels on even if the view has them hidden), and downloads PNG and PDF. `window.blueprintCaptureDrawing()` returns `{png, pdf, stem}` for a headless capture.

View buttons: Iso / Front / Side / Top stay one segmented control. Custom scenes are separate wrapping buttons underneath.

## Rebuild the IIFE (after editing `main.js` / `pivotNav.js` / `doors.js` / `interactions.js` / `chrome.js` / `coopRange.js` / `materials.js` / `depthPeel.js` / `edges.js` / `clipGeometry.js` / `sectionCaps.js` / `annotations.js` / `drawing.js` / `ifcInspector.js` / `ifcTree.js` / `elementActions.js` / `gesture.js` / `meshIdentity.js` / `homeLive.js` / `feedback.js` / `catalogue.js` / `realistic.js` / `assetSlots.js`)

```bash
cd src/blueprints/viewer
npm ci
npm run build
```

`viewer.iife.js` is committed so Python export does not need Node at runtime. The `viewer-js` workflow rebuilds it and fails if the committed bundle differs. Copy/sync into `docs/viewer/` via `ensure_viewer_shell()` on publish, or copy manually after build.
